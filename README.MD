# Music Radio

Jewish radio, streaming straight to your desk and your pocket.

A Kotlin Multiplatform rewrite of [KdroidRadioDesktop](https://github.com/kdroidFilter/KdroidRadioDesktop),
built on the Compose Multiplatform / Nucleus template that [Edge Translator](https://github.com/NucleusFramework/EdgeTranslator)
uses: one `shared` module holding all the logic and the whole UI, with paper-thin platform entry points.

## What changed from the original

| | KdroidRadioDesktop | Music Radio |
|---|---|---|
| Targets | Desktop (JVM) only | Desktop **and** Android, one shared UI |
| Audio | VLCJ - needs VLC installed on the machine | [Compose Media Player](https://github.com/kdroidFilter/Compose-Media-Player) audio module: Media3 on Android, Rodio on desktop. Nothing to install. |
| Architecture | PreCompose, several view models, mutable state scattered across managers | Single-state MVI: one `AppState`, one `AppViewModel`, one `onIntent` |
| Navigation | PreCompose router | Navigation 3 back stack |
| DI | Hand-wired singletons | [Metro](https://github.com/ZacSweers/metro) compile-time graph |
| Theme | Fixed palettes plus a palette/AppBar-style picker | One accent seed, whole Material 3 scheme generated by MaterialKolor |
| Dropped | contact form with SMTP, Ko-fi post scraper, AppBar-style picker, window-placement picker | - |
| Added | favorites, station search, category filter, adaptive phone layout | - |

Everything the app is actually for - the 16 stations, the multi-channel groups (Kol Hay Music alone
carries 38 channels), the Hebrew / English / French interface - carries over unchanged.

## Layout

```
shared/       logic, Compose UI, player, data
desktopApp/   desktop entry point (Nucleus decorated window)
androidApp/   Android entry point (single activity)
```

## Running from source

```bash
./gradlew :desktopApp:run           # desktop
./gradlew :androidApp:assembleDebug # Android APK
```

Hot reload:

```bash
./gradlew :desktopApp:hotRun --auto
```

## Building distributables

### Desktop installers

Two packagers are wired up. **jpackage** is the default: it needs nothing beyond the JDK and Node,
and the runtime it bundles carries no redistribution strings.

```bash
./gradlew :desktopApp:packageNsis   # Windows .exe installer
./gradlew :desktopApp:packageDeb    # Linux .deb
./gradlew :desktopApp:packageDmg    # macOS .dmg
```

**GraalVM native images** start faster and use less memory, at the cost of a ~1 GB toolchain
download per machine. This project is configured for *Oracle* GraalVM, whose terms permit
redistribution only while you charge nothing for the result - switch to
`GraalvmDistribution.COMMUNITY` in `desktopApp/build.gradle.kts` if that ever stops being true.

```bash
./gradlew :desktopApp:packageGraalvmNsis
./gradlew :desktopApp:packageGraalvmDeb
./gradlew :desktopApp:packageGraalvmDmg
```

Output lands under `desktopApp/build/compose/binaries/`.

### Android

```bash
./gradlew :androidApp:assembleDebug     # installable straight away, debug-signed
./gradlew :androidApp:assembleRelease   # unsigned unless the keystore variables are set
./gradlew :androidApp:bundleRelease     # .aab for Play
```

APKs land in `androidApp/build/outputs/apk/`, bundles in `androidApp/build/outputs/bundle/`.

For a signed release, point the build at a keystore through the environment - nothing about
signing is committed:

```bash
export ANDROID_KEYSTORE_FILE=/path/to/release.jks
export ANDROID_KEYSTORE_PASSWORD=...
export ANDROID_KEY_ALIAS=...
export ANDROID_KEY_PASSWORD=...
./gradlew :androidApp:assembleRelease
```

Create one with:

```bash
keytool -genkeypair -v -keystore release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias musicradio
```

### Releases

Pushing a `v*` tag runs `.github/workflows/release.yaml`, which builds Windows, Linux (x64 and
ARM64), macOS (Apple Silicon and Intel) and Android, then opens a GitHub Release with everything
attached. A tag containing `-alpha`, `-beta` or `-rc` publishes as a prerelease.

```bash
git tag v1.0.0 && git push origin v1.0.0
```

Android signing in CI comes from four repository secrets. `ANDROID_KEYSTORE_BASE64` is the keystore
itself, base64-encoded (`base64 -w0 release.jks`); the rest mirror the local variables above:

| Secret | Purpose |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | the keystore file |
| `ANDROID_KEYSTORE_PASSWORD` | store password |
| `ANDROID_KEY_ALIAS` | key alias |
| `ANDROID_KEY_PASSWORD` | key password |

Without them the workflow still completes but publishes an **unsigned** APK, which Android refuses
to install - set them before cutting a real release.

## Requirements

- JDK 25 or newer for the desktop app
- JDK 17 target for `shared` and Android; Android minSdk 26

### Behind a TLS-intercepting proxy

If your network terminates TLS (NetFree, corporate filtering), the JVM will not trust the
interception CA and every download fails with `PKIX path building failed`. On Windows, point Java at
the system root store for the build:

```powershell
$env:GRADLE_OPTS = '-Djavax.net.ssl.trustStoreType=Windows-ROOT'
```
