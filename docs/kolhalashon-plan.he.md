# שילוב שיעורי קול הלשון ב-Music Radio - תוכנית

המטרה: להשמיע שיעורים של רב בתוך Music Radio באותה תחושה שבה האפליקציה משמיעה רדיו, אבל עם כל מה
שאודיו לפי דרישה צריך ושידור חי לא: מיקום, סרגל התקדמות, המשך מהמקום שנעצרת, ורשימה שאפשר לדפדף בה.

הרב הראשון: **הרב אלימלך בידרמן, `ravId = 674`** (5852 שיעורים לפי
`Ravs/WebSite_GetRavShiurimCount/674/-1`). המבנה נושא עוד רבנים בלי שינוי; רק רשומת הקטלוג היא לכל רב.

מקורות: `C:/dev/kolhalashon-api/API-SPEC.md`, הספרייה `kolhalashon-kmp` (זו שהאפליקציה תשתמש בה),
ו-`kolhalashon-node` (אותו משטח, לא בשימוש כאן).

> גרסה אנגלית של אותו מסמך, לצורכי הריפו הציבורי: `docs/kolhalashon-plan.md`.

## 1. מה הקוד הקיים נותן, ומה לא

בדקתי את זה לפני שתכננתי; כל שורה כאן הכריעה משהו בהמשך.

| ממצא | איפה | משמעות |
| --- | --- | --- |
| ל-`RadioPlayer` **אין מיקום, אורך או seek**. כתוב שם: "deliberately absent - every source here is a continuous broadcast with neither" | `player/RadioPlayer.kt` | השינוי הגדול היחיד. כל השאר תוספתי; זה שינוי בממשק שיש לו שלושה מימושים. |
| המנוע **כן** יודע: `seekTo(long)`, `currentPosition()`, `currentDuration()`, `setRate(float)` | `composemediaplayer-audio` 0.11.4, אומת עם `javap` | לא צריך תלות אודיו חדשה בדסקטופ ובווב. |
| אנדרואיד לא משתמש במנוע הזה בכלל, אלא ב-`MediaController` שקשור ל-`PlaybackService` | `player/MediaSessionRadioPlayer.kt` | באנדרואיד seek מגיע בחינם (`controller.seekTo`, `setMediaItem(item, startMs)`), וזה גם המקום היחיד שבו גם ההתראה של מערכת ההפעלה צריכה סרגל. |
| `StreamRadioPlayer` כבר דוגם את המנוע כל 250ms | `player/StreamRadioPlayer.kt` | דיווח המיקום רוכב על הלולאה הקיימת; אין טיימר שני. |
| הקטלוג הוא דאטה סטטית: `Station` מחזיק `List<Channel>` קבוע, כל אחד עם `streamUrl` מילולי | `domain/Stations.kt` | רב לא יכול להיות `Station`. זה סוג אחר של דבר וצריך טיפוס משלו. |
| השמירה היא קובץ `key=value` שטוח אחד, שנכתב מחדש במלואו בכל שינוי | `data/SnapshotCodec.kt`, `data/AppStore.kt` | התקדמות לכל שיעור **אסור** שתשב שם: היא משתנה כל כמה שניות והייתה גוררת כתיבה מחדש של קובץ ההגדרות איתה. |
| MVI עם מצב יחיד: `AppState` אחד, `onIntent` אחד, ו-`reduce` ממצה על `AppIntent` | `app/AppViewModel.kt` | כל intent חדש חייב להיכנס ל-`reduce` ול-`afterReduce`, אחרת הבילד נשבר. זו תכונה, לא מכשול. ללכת איתה. |
| Ktor כבר תלות ב-`commonMain`, עם מנוע לכל פלטפורמה | `shared/build.gradle.kts`, `platform/HttpClientFactory.kt` | `KolHalashonClient` יכול לשאול את ה-`HttpClient` של האפליקציה במקום לפתוח בריכת חיבורים שנייה. |
| ארבעה יעדים: android, jvm, js, wasmJs | `shared/build.gradle.kts` | `kolhalashon-kmp` מפרסם בדיוק את הארבעה האלה. |
| מקשי מדיה וחלונית המדיה של מערכת ההפעלה כבר עוברים דרך `AppIntent` | `bindMediaControls()` | הבא/הקודם צריכים להיות "שיעור הבא" במצב שיעור ו"תחנה הבאה" במצב רדיו. הסתעפות אחת, לא מסלול שליטה שני. |
| מטא-דאטה של ICY נדגמת כל 20 שניות בזמן שסטרים פעיל | `watchNowPlaying()` | חייב להיות מדולג עבור שיעורים; ל-MP3 אין ICY, וזו בקשה מבוזבזת מול מארח שמוגן ב-Cloudflare. |
| כל מחרוזת גלויה קיימת ב-`values`, `values-fr`, `values-he`, `values-iw` | `composeResources/` | ארבעה קבצים לכל תווית, כש-`values-iw` נוצר מ-`values-he` על ידי הבילד. |

## 2. הקונספט: רב הוא תחנה מסוג אחר

תחנת רדיו היא **כתובת אחת אינסופית**. רב הוא **קטלוג עם סמן לתוכו**. מידול של השני כמו הראשון הוא
בדיוק מה שהיה מכער את הפיצ'ר, ולכן אנחנו לא עושים את זה.

מה שהמשתמש רואה:

- בגריד התחנות, תחת הקטגוריה **Torah**, כרטיס של הרב. אותו גודל, אותו טיפול בתמונה, כדי שייקרא כחלק
  מהאפליקציה ולא כאורח.
- לחיצה עליו **לא** מפעילה סטרים. היא פותחת את **מסך הרב**, ובמקביל ברקע מחשבת ומתחילה את השיעור
  הנכון (סעיף 4). עד שהמסך סיים להיצייר, הקול כבר בדרך.
- מסך הרב הוא הסייר: המשך / שיעורים / תיקיות.
- מסך הנגן הוא נגן הרדיו הקיים ועוד כל מה ששידור חי לא יכול להחזיק: סרגל, זמן שעבר ונשאר, דילוג
  15 שניות, שיעור קודם והבא.

מה שהקוד רואה: `PlaybackSource` הופך ל-sealed עם שני מקרים, `Radio(channelId)` ו-`Shiur(ravId, fileId)`.
כל התנהגות קיימת נשענת על `Radio`; מסלול הרדיו לא משנה צורה.

## 3. ארכיטקטורה, שכבה אחר שכבה

### 3.1 ספריית הלקוח

`kolhalashon-kmp` יושבת ב-`dev.kdroid:kolhalashon:0.1.0`, ומכוונת ל-android/jvm/js/wasmJs. התאמה
מדויקת לאפליקציה הזאת.

**חסרה בה קריאה אחת שהתוכנית צריכה**: רשימת שיעורים בתוך תיקייה. ה-DTO זהה לחלוטין ל-`ravShiurim`;
רק הנתיב ומשמעות `GeneralID` משתנים (`Search/WebSite_GetShiurimUnderNode`, `GeneralID = folderId`,
לפי API-SPEC 3.8 ו-6.1). להוסיף לספרייה ולחתוך **0.2.0**:

```kotlin
public suspend fun shiurimUnderFolder(
    folderId: Int,
    fromRow: Int = 0,
    rowsPerPage: Int = 24,
    order: SearchOrder = SearchOrder.NEWEST_FIRST,
    language: ShiurLanguage = options.language,
): ShiurPage
```

אופציונלי, בשביל צ'יפי השפה בסעיף 4.1: `ravSubjects(ravId): List<FilterItem>`, שקורא שורות
`ResultType == 3` כשפות שלרב הזה באמת יש (`Search/WebSite_GetRavSubjectsIDs`, API-SPEC 6). בלי זה,
מקודדים קשיח עברית + אידיש + הכל עבור בידרמן, ומוסיפים את הקריאה באבן דרך מאוחרת יותר.

**איך האפליקציה תלויה בה.** שלוש אפשרויות, והמחיר האמיתי של כל אחת:

| | עובד מקומית | עובד ב-CI | מחיר |

### 3.3 נגן: `RadioPlayer` שיודע seek

השינוי השובר היחיד, מוחזק קטן ככל האפשר. שידורים חיים ממשיכים לענות `seekable = false` ו-
`durationMs = 0`, כך שכלום במסלול הרדיו לא משתנה על המסך.

```kotlin
@Immutable
data class PlaybackProgress(
    val positionMs: Long = 0,
    val durationMs: Long = 0,     // 0 = לא ידוע, או חי
    val seekable: Boolean = false,
)

interface RadioPlayer {
    val status: StateFlow<PlaybackStatus>
    val progress: StateFlow<PlaybackProgress>                                // חדש

    fun play(url: String, startAtMs: Long = 0, seekable: Boolean = false)    // שני פרמטרים חדשים, עם ברירת מחדל
    fun seekTo(positionMs: Long)                                             // חדש
    fun setRate(rate: Float) = Unit                                          // חדש, אופציונלי, ברירת מחדל ריקה
    // resume / pause / stop / setVolume / release / setNowPlaying ללא שינוי
}
```

לכל מימוש:

- **`StreamRadioPlayer`** (jvm + web). לולאת ה-`sync()` של 250ms כבר רצה; מוסיפים לה
  `backend.currentPosition()` ו-`currentDuration()` ומפרסמים `progress`. `startAtMs` צריך שדה
  pending-seek חד-פעמי: Rodio לא יכול לעשות seek לפני שהזרם נפתח, אז מחזיקים את הערך ויורים `seekTo`
  בטיק הראשון שמדווח אורך שאינו אפס, ואז מנקים. `seekable` מגיע מהקורא ולא מנוחש, כי האפליקציה יודעת
  איזה משני הסוגים היא ביקשה.
- **`MediaSessionRadioPlayer`** (android). `startAtMs` ממופה ישירות ל-`setMediaItem(item, startPositionMs)`,
  ו-`seekTo` ל-`controller.seekTo`. המיקום ב-Media3 אינו דחיפה, אז מוסיפים טיקר של 500ms על ה-main
  looper, שרץ **רק** כאשר `seekable && status.active`. מסלול הרדיו נשאר חינמי כמו שהוא היום. בנוסף
  להנגיש את פקודות `COMMAND_SEEK_*` כדי שההתראה תצייר סרגל.
- **`SilentRadioPlayer`** - לעקוב אחרי מיקום מדומה, כדי שבדיקות ותצוגות מקדימות יישארו כנות.

ל-`MediaControls` של Nucleus (דסקטופ) יש גם מיקום ב-MPRIS/SMTC; לחבר ב-M5, לא לפני.

### 3.4 נתונים: התקדמות, בקובץ משלה

`state.txt` נשאר כמו שהוא. קובץ שני, `shiurim.txt`, מחזיק את הסמן:

```
674/1234567=845000,3612000,0,1755900000
674/1234512=3600000,3612000,1,1755813600
        ^rav/fileId  ^posMs  ^durMs ^finished ^updatedAtEpochSeconds
```

- אותה משמעת פענוח כמו `SnapshotCodec`: שורה פגומה נזרקת, לעולם לא מפילה.
- **חסום ל-500 שורות LRU**, מפנה את `updatedAt` הישן ביותר. 500 שורות הן כ-20KB ומכסות שנים של
  האזנה; גדילה בלי גבול על טלפון היא לא אופציה.
- נכתב **מושהה**: כל 5 שניות בזמן ניגון, ומיידית ב-pause, ב-stop, בהחלפת שיעור וב-`onCleared`. לא
  בכל טיק מיקום.
- `state.txt` מקבל מפתח אחד, `lastShiur=674/1234567`, כך ש-`resumeOnLaunch` יכסה גם שיעורים.

```kotlin
data class ShiurProgress(
    val positionMs: Long,
    val durationMs: Long,
    val finished: Boolean,
    val updatedAt: Long,
)

interface ProgressStore {
    fun all(): Map<String, ShiurProgress>       // מפתח = "$ravId/$fileId"
    fun put(key: String, progress: ShiurProgress)
    fun clear()
}
```

**"הסתיים"** הוא `finished == true` ברגע שנקבע, או `durationMs > 0 && positionMs >= durationMs - 30_000`.
הדגל נשמר ולא מחושב מחדש, כי שיעור שהאורך שלו מעולם לא נפתר אחרת לעולם לא ייחשב כנגמר.

### 3.5 הגדרות: העדפת שפה אחת לשיעורים, גלובלית

בדיוק כפי שביקשת: השפה נבחרת פעם אחת וחלה על כל הרבנים.

```kotlin
// domain/AppData.kt, על UserSettings
val shiurLanguage: ShiurLanguage? = null,   // null = ללכת אחרי שפת האפליקציה/המכשיר
```

- `null` (ברירת המחדל) נפתר מ-`settings.uiLanguage`: `he -> HEBREW(1)`, `en -> ENGLISH(2)`,
  `fr -> FRENCH(4)`. שפת האפליקציה עצמה כבר `auto` כברירת מחדל, אז התקנה טרייה הולכת אחרי המכשיר.
- בחירת צ'יפ במסך של רב כלשהו כותבת ערך מפורש; הוא גלובלי ומיידי.
- מפתח `shiurLanguage` ב-`SnapshotCodec` (הגדרה שמדלגת על הקודק שוכחת את עצמה בשקט, ראה AGENTS.MD),
  ועוד שורה ב-`SettingsScreen` כדי שיהיה ניתן לגילוי גם מחוץ למסך הרב.
- **כלל נפילה**: אם השפה שנפתרה מחזירה אפס שיעורים לרב הזה, ניסיון חוזר אחד עם `ShiurLanguage.ANY`
  והערה בשורה ("אין שיעורים ב<שפה>, מוצגים כל השיעורים"). בידרמן בצרפתית היה אחרת מסך ריק שנראה
  כמו באג.

### 3.6 ריפוזיטורי

`data/ShiurRepository.kt` - הדבר היחיד שמדבר עם `KolHalashonClient`.

- גישה מדופדפת לפי `(ravId, language, folderId?)`, גודל עמוד 24 (זה של האתר עצמו), טעינה מוקדמת
  כשהרשימה במרחק 6 שורות מהסוף.
- מטמון בזיכרון לעמודים שנטענו לכל מפתח, נזרק בהחלפת שפה.
- **עמוד 0 נשמר גם לדיסק**, ב-`cache/rav-674-1.json` עם TTL של 12 שעות, מסיבה אחת ששווה את הקוד:
  כתובת האודיו היא `files/GetMp3FileToPlay/{fileId}`, פונקציה טהורה של המזהה. לכן הפעלה קרה עם עמוד 0
  מהמטמון ושורת התקדמות יכולה **להמשיך ניגון בלי אף קריאת API**. זה הגידור הטוב ביותר מול challenge
  של Cloudflare.
- שגיאות נחשפות לפי סוג, לעולם לא משוטחות: `KolHalashonRateLimitedError` נותן "האתר מגביל קצב, נסה
  שוב בעוד כמה דקות" ו**בלי ניסיון חוזר אוטומטי** (ניסיון חוזר הוא מה שמשאיר challenge בחיים,
  API-SPEC 1.3); `KolHalashonLockedError` נותן תג מנעול; כל השאר נופל להודעת הכשל הגנרית הקיימת.

## 4. ההתנהגות, במפורש

### 4.1 כניסה לרב - איזה שיעור מתנגן

```
onOpenRav(ravId):
  lang  = settings.shiurLanguage ?: מתוך settings.uiLanguage
  page  = repo.page(ravId, lang, fromRow = 0)            # NEWEST_FIRST, 24 שורות
  אם page ריק ו-lang != ANY:
      page = repo.page(ravId, ANY, 0); הערה("נפילה לכל השפות")

  candidates = page.items.filter { it.hasAudio && !it.isLocked }
  target = candidates.firstOrNull { !progress.isFinished(it) }   # החדש ביותר שלא הסתיים
  אם target == null ויש עוד עמודים:
      ללכת עד 4 עמודים נוספים, ואז לוותר ולקחת את candidates.first()

  saved   = progress[target]
  startAt = אם saved == null אז 0, אחרת max(0, saved.positionMs - 10_000)
  player.play(target.audioUrl, startAtMs = startAt, seekable = true)
```

ההליכה האחת הזאת מממשת את שלושת הכללים שביקשת:

- לא שמע כלום - השיעור החדש ביותר, מ-0;
- התחיל ולא סיים - אותו שיעור בדיוק, **במיקום השמור פחות 10 שניות**, עם רצפה ב-0;
- כבר סיים את החדש - מדולג, ונלקח הבא אחריו שלא הסתיים, וכך הלאה לכמה שהסתיימו.

**הסתייגות לגבי סדר, שחייבת להיסגר לפני שבונים.** `SearchOrder = 7` הוא ברירת המחדל של האתר עצמו
בעמוד הרב, וזה מה ש-`kolhalashon-kmp` מכנה `NEWEST_FIRST`. אבל API-SPEC 3.3 אומר במפורש ש*איזה
מזהה אומר "חדש ראשון" לא נקבע*. לאמת ב-M0 על ידי משיכת שני עמודים והשוואת `RecordDate`. אם 7 אינו
"חדש ראשון", למצוא את המזהה שכן, או למיין בצד הלקוח לפי `recordDate` בתוך העמודים שבידינו.

### 4.2 טרנספורט

| פקד | משמעות |
| --- | --- |
| שיעור קודם | צעד אחד **למעלה** ברשימה הגלויה (חדש ראשון), כלומר חדש יותר |
| שיעור הבא | צעד אחד **למטה**, כלומר ישן יותר. הכיוון שאליו "להמשיך" רץ |
| דילוג 15 שניות אחורה/קדימה | `seekTo(position -/+ 15_000)`, מוגבל ל-`0..duration` |
| לחיצה ארוכה על כפתורי הדילוג | גלילה רציפה, ראה למטה |
| סרגל ההתקדמות | גרירה, מחויב בשחרור |
| נגן/השהה | ללא שינוי |

המרווח הוא קבוע (`SKIP_STEP_MS = 15_000`). הגדרה עבורו היא תוספת מאוחרת וזולה.

**לחיצה ארוכה.** מטופלת כולה ב-UI; הנגן נוגע פעם אחת, לא שישים:

```
בלחיצה:
  אחרי 400ms של החזקה, מתחיל טיק כל 100ms
  בכל טיק: preview += step * direction
  הצעד גדל 1ש -> 2ש -> 5ש -> 10ש לכל שנייה שלמה של החזקה, חסום ב-10ש
  (כלומר כ-10 דקות אודיו ב-6 שניות של לחיצה)
  הסרגל ותווית הזמן עוקבים אחרי preview בזמן אמת
בשחרור:
  player.seekTo(preview); preview = null
```

מחויב בשחרור ולא בכל טיק - זה מה שישאיר את זה חלק בשלושת המימושים. שישים `seekTo` בשנייה היו
מגמגמים ב-Rodio ומכסחים את הבאפר ב-ExoPlayer.

**מקשי מדיה וההתראה.** `MediaCommand.Next` ו-`Previous` כבר עוברים דרך `AppIntent`; מסתעפים על
`PlaybackSource` כך שהם יהיו *שיעור* הבא/הקודם במצב שיעור ו*תחנה* הבאה/הקודמת במצב רדיו. הסתעפות
אחת ב-`bindMediaControls`.

### 4.3 ניהול המיקום

- כל פליטת `progress` עם `seekable = true` מעדכנת מצב בזיכרון; לחנות נכתב לפי ההשהיה שבסעיף 3.4.
- בסיום טבעי (`position >= duration - 1s` והמנוע במצב idle) מסמנים **הסתיים**, ואז מתקדמים אוטומטית
  לשיעור הבא ברשימה כלפי מטה. זה מה שגורם לרב להרגיש כמו תחנה: הוא ממשיך לנגן.
- החלפת שיעור, השהיה, עצירה ו-`onCleared` כולם שוטפים לדיסק קודם.
- דגימת ICY מותנית ב-`source is Radio`.

## 5. ממשק

### 5.1 מסך הרב - `AppKey.Rav(ravId)`

```
+---------------------------------------------+
| <-  [דיוקן]     הרב אלימלך בידרמן            |
|                 5,852 שיעורים                |
|                 [ עברית ] [ אידיש ] [ הכל ]  |  <- צ'יפי שפה, העדפה גלובלית
+---------------------------------------------+
|   [ המשך ]     [ שיעורים ]     [ תיקיות ]    |  <- בורר מקטעים
+---------------------------------------------+
|  +---------------------------------------+  |
|  | > המשך: <כותרת>                        |  |  <- הבחירה מסעיף 4.1, כרטיס גדול
|  |   14:05 / 60:12   #####.........      |  |
|  +---------------------------------------+  |
|  נשמעו לאחרונה ...                          |
+---------------------------------------------+
```

- לשונית **שיעורים**: `LazyColumn` מדופדף. שורה = כותרת, `RecordDate` כתאריך עברי, משך, פס התקדמות
  דק כשנשמע חלקית, וי כשהסתיים, ותג מנעול כש-`isLocked`.
- לשונית **תיקיות**: `ravFolders(674)`, לחיצה על תיקייה, ואז `shiurimUnderFolder(folderId)` עם אותה
  שורה ופירורי לחם לחזרה. תיקיות עם `hiddenFromPhone` / `hiddenFromWeb` מסוננות לפי פלטפורמה,
  השדות כבר קיימים על `RavFolder`.
- הטעינה היא shimmer מעל הרשימה ולא ספינר מעל המסך; כרטיס ההמשך מצויר מהמטמון ברגע שהוא ידוע.

### 5.2 מסך הנגן

להרחיב את `NowPlayingScreen` ולא לפצל אותו. התמונה, בלוק הכותרת ופקד עוצמת הקול זהים, ופיצול פירושו
שני מקומות לתקן בהם באג פריסה. מותנה ב-`progress.seekable`:

```
              [ תמונה ]
            הרב אלימלך בידרמן
              <כותרת השיעור>
            <תאריך> - <תיקייה>

    #######.....................
    14:05                 -46:07

     |<<   -15   נגן   +15   >>|
                [ 1.0x ]
```

הרדיו שומר בדיוק על הפריסה שיש לו היום; כל אלמנט למעלה מופיע רק תחת `seekable`.

### 5.3 מחרוזות

כל תווית חדשה נוחתת ב-`values/`, `values-fr/`, `values-he/` (`values-iw` נוצר). בגדול: שם הרב, שלוש
תוויות הלשוניות, תוויות צ'יפי השפה, "המשך האזנה", "הסתיים", "תוכן נעול", "אין שיעורים בשפה זו",
והודעת הגבלת הקצב.

## 7. סיכונים, בכנות

1. **CORS בווב לא נבדק.** API-SPEC 7.1 משאיר את זה `UNKNOWN`. הניגון עצמו כנראה בסדר, אלמנט
   `<audio>` טוען cross-origin בלי CORS, אבל קריאות ה-JSON מ-wasmJs צריכות
   `Access-Control-Allow-Origin` ואולי לא יקבלו אותו. GitHub Pages הוא סטטי, אז אין פרוקסי להתחבא
   מאחוריו. **אם M0 עונה שלילית, בילד הווב פשוט מסתיר את כרטיס הרב** והפיצ'ר יוצא בדסקטופ
   ובאנדרואיד. להכריע את זה ב-M0, לא ב-M4.
2. **Cloudflare.** תריסר בקשות בדקה מפילים challenge שלא מתנקה מעצמו (API-SPEC 1.3). ההקלות כבר
   בתוכנית: לקוח משותף אחד, מרווח מינימלי של שנייה, concurrency 1, מטמון דיסק לעמוד 0, המשך ניגון
   בלי אף קריאת API, ואפס ניסיונות חוזרים על challenge. אבל התקרה אמיתית, ודפדוף מהיר בין 5852
   שיעורים יגיע אליה. לטעון מראש בשמרנות.
3. **`SearchOrder = 7` אולי לא אומר "חדש".** ראה 4.1. M0 סוגר את זה.
4. **תוכן נעול ותוכן לנשים בלבד.** שיעורים עם `isLocked` מוחרגים מהבחירה האוטומטית ומוצגים עם תג,
   ולעולם לא מנוגנים בעקיפה. הספרייה מסרבת למסור את הכתובת שלהם, וזה נכון. `isWomenOnly` דורש
   הכרעה מוצרית: האתר מדכא את התצוגה המקדימה שלהם לגמרי.
5. **משך לפני ניגון.** `ShiurDuration` מגיע עם הרשימה, כך שטבעות ההתקדמות מציירות בלי לפתוח את
   הקובץ. להתייחס ל-`currentDuration()` של המנוע כסמכותי ברגע שהוא ידוע וליישב ביניהם, הם ייחלקו
   מדי פעם בשנייה או שתיים.
6. **היקף.** M1 נוגע בממשק עם שלושה מימושים על שלוש פלטפורמות, שלאחת מהן (ווב) אין דיבאגר נוח.
   לתקצב בהתאם; שאר התוכנית תוספתית.
